# Console v5 审查问题的界面修复与验收映射

本文对应 85 项审查中的界面部分，记录实际修改位置、跨端契约和剩余边界。源码入口是 `src/ui/console-v5/`；旧 React 控制台未作为本轮发行入口修改。表中的“已接”表示实现已经落地，完整类型检查、服务端回归、真实浏览器运行结果见 [本轮验证记录](console-audit-closure-20261022.md)。

## 状态与读写规则

Task 的请求状态、后台执行事实、阶段结果、人工验收、交付确认以及来源新鲜度分别保留。主徽章使用请求对应的执行状态；阶段已完成但请求仍开放时，额外显示“执行阶段已结束”，仅在验收状态为 pending 时显示“结果待验收”，已有接受或驳回结论继续保留。请求已结束但后台仍执行、后台结果待核对时，同一行同时显示这两个事实。`handed_off` 保留交接结果，不转换为普通完成。

界面不再将没有后台执行一律称为“等待下一步”；共享文案是“当前无后台执行”。原因由后端提供，详情保留实际原因、最终确认错误、阶段总结和操作能力。“中断”也不再自动承诺可以恢复；恢复按钮以实际能力为条件。

读请求按资源分别去重、取消、退避。强制读和写后失效建立新请求身份，迟到的旧请求不能写回新缓存；强制业务 GET 带 `fresh=1` 通知服务端对应资源重读，缓存键保持原路径。失败保留最近数据并显示来源状态；过期执行时钟使用共享 `executionTimeEnd` 固定到可证明的时间。配置刷新采用基线、当前输入、服务器保存配置的三方合并，冲突字段必须明确选择。写操作中，已知无副作用的拒绝允许重新编辑并使用新请求标识，未知结果锁住原内容，只查询原请求回执。

| R06 | `sourceWarning`、`staleNotice`、全局来源提示均呈现 `refreshing/stale/loading/offline/error`。 | 同一来源的最近确认时间保留。 |

| R08 | 列表、详情共同消费来源降级与 `executionTimeEnd`；`runBadges` 显示上次确认。 | UI 不重新推断进程存活。 |
| R09 | 详情使用返回的已知阶段、warnings、sources；`phaseCards` 保留成功阶段入口。 | 部分详情聚合由 router 负责；已知证据不因另一个阶段失败而整体隐藏。 |
| R10 | `routePaths` 仅加载页面需要的资源；全局会话不强迫先选项目；节点配置只强制读取目标节点。 | 范围索引下推由 feed 负责；本轮并未声称建立全新的分布式增量数据库。 |
| R11 | `refresh/schedulePoll` 不再由全局在途锁阻塞独立资源；退避归各缓存项；手动刷新会重新发起。 | 文案为“每 N 秒检查更新”，不保证每 N 秒取得全网新状态。 |
| R12 | `presentation.ts: elapsed` 使用共享时间函数；`tickClock` 到期冻结；`dom.ts` 不再跳过新 `data-observed`。 | 失败和失联快照不靠客户端秒表表现为仍在执行；浏览器检查两次新观测能更新同一时钟元素。 |
| R13 | `resources.ts: validate` 校验总览、节点嵌套集合、详情、文件、会话、用量、活动、回执等主要结构；`schedulePaint` 有错误边界和重试/诊断入口。 | 校验覆盖使用中的关键字段与集合，未宣称实现全接口的完整 JSON Schema。 |
| R14 | 页面隐藏、离线、离开时取消资源、命令输出、通知读取；取消不触发 `loaded` 再次读；`ensureRoute` 检查可见性。 | 文件追加分页也绑定取消信号，旧页不能追加到新版本。 |

## 二次检查额外发现并修复的具体问题

1. 文件 diff 的“读取更多”原来不带取消信号，手动刷新后晚到页还能影响当前文件；现在有取消、版本、游标、缓存身份检查。
2. 未知写回执查询若缺少目标作用域，带 `id/projectId/previewId` 的动作会一直查不到原回执；现在原请求体与回执列表都保留该作用域。
3. DOM 差量更新原来对 `data-elapsed` 整节点跳过，导致新 `data-observed` 永不更新；真实运行即使持续收到新确认，也会在 30 秒后被旧确认时间冻结。已取消此特殊跳过并增加浏览器断言。
4. 写请求返回成功 HTTP 但正文不是 JSON、是 null、数组或原始值时，不能据此认定没有副作用。现在保留未知结果和原请求身份。
5. 开放 Task 的阶段完成待验收引入独立维度后，三参数 `taskStage` 不能再用于等待导航组；否则总览列出、下钻又消失。已分开分组和验收维度并加入回归。
6. 已明确拒绝的未知查询恢复后，对话框按钮应恢复原操作名，不能继续写“查询原提交结果”；已修复。
7. 配置刷新中的复选框冲突选择按钮不能触发外层 label 的默认切换；冲突选择显式阻止该默认动作。
8. 新建根目录不能借“真实当前 revision”绕过已有 ID 检查；界面显示碰撞，提交明确 `create`，服务端保持严格 CAS。
9. 操作回执存储时间是 ISO 字符串，界面不能按纯数字时间处理；现在规范接受数字/ISO并拒绝无效值。
10. `state=completed` 表示请求已有应答，不能掩盖 response/子回执仍 accepted；此时继续显示“请求已接收，执行待结束”并保留原请求查询入口，共享递归识别函数检查聚合子目标。
