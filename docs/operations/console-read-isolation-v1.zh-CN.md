# Console 隔离读取 v1 与进程退出监督

本文记录 2026 年 11 月 1 日止损版本的维护契约，范围是每次请求独立启动的读取进程，以及监督器的进程生命周期修复。完整详情重建、读取进程复用不属于此版本。

## 固定读取边界

经过认证的 Console GET 使用固定的节点协议 `/workbench/isolated-v1/...`。白名单包括元数据、执行列表和摘要、Task 索引、会话标题、总览与用量、调用与事件、Task 消息状态。它不是 SQL、任意文件、模块或 shell 命令接口。原有 Owner/节点认证和工作区授权仍然有效。

每次读取在独立 Node 子进程中执行。加载查询模块前，子进程启用不可逆的 `useReadonlyDatabases()` 模式。SQLite 使用 `readonly: true`、`fileMustExist: true`、`query_only = ON` 和 1,000 毫秒锁等待上限；不创建或 chmod 状态目录，不修改日志模式，不执行迁移。数据库缺失或结构不兼容时报告读取失败，读取器不得自行修复。固定读取器不启动 `SessionRuntime`、改动捕获、命令执行或额外监听服务。

父进程依据 `src/console-workbench/read-process.ts` 执行以下限制：

| 限制 | 数值 | 含义 |
| --- | --- | --- |
| 同时读取 | 1 | 每个 Core 的读取池 |
| 排队读取 | 8 | 超出后直接报告繁忙 |
| 读取期限 | 5,000 毫秒 | 从入队计时，包含排队、启动、查询和结果交付 |
| 请求大小 | 64 KiB | UTF-8 序列化请求 |
| 结果大小 | 8 MiB | 包含协议外层的子进程序列化响应 |

期限由父进程计时，子进程同步 SQLite 或文件 I/O 阻塞不会阻止该计时器。超时或取消只终止本次读取的 `ChildProcess`；直到收到该子进程的 `close` 才释放执行名额，避免连续失败无限创建替代进程。不会以 Task 进程、整个进程组或请求提供的 PID 为终止目标。子进程仅继承明确允许的环境变量，不继承模型凭据、QuayMesh 密钥或 `NODE_OPTIONS`。

## 共享刷新与请求取消

`WorkbenchFeed` 对同一节点、同一资源共享一次正在进行的刷新，并保留上次成功数据和原始观察时间。页面通常每轮最多等 1,200 毫秒，之后可先返回 loading/refreshing 或部分数据，共享刷新继续完成。打开页面不能刷新旧证据的时间。刷新失败时保留已有数据、显示真实错误并按原退避机制重试，不能转换成成功的空结果。

节点本地读取路由继承自己的 HTTP 取消信号，可以取消对应的隔离读取。Owner 聚合页面不会把单个浏览器请求的取消信号绑定到共享刷新；关闭一个请求不能取消其他页面仍需要的数据获取。继续执行的本机刷新仍受读取器 5 秒期限约束；远端请求另有传输期限。两种期限不能混为一谈。

## 混合版本与临时限制

本机和远端分派前都先选择版本化 GET 路径。旧节点没有该路由时返回 `node_read_upgrade_required`，保留可用缓存并提示升级，**不得回退请求旧的同步读取路由**。已实现端点返回的任务、文件或命令不存在，仍按原业务错误处理，不能误报版本缺失。读取失败本身不代表节点心跳或任务执行已停止。

此版本的执行/Task 详情只提供已保存摘要：`complete: false`，明确列出待取得的详情，并禁用依赖完整证据的操作。详情空数组是尚未确认，不能解释为文件、命令或代理数量为零。文件详情、补丁、命令输出、工作区会话历史和审计读取暂不可用。消息状态只有单独的权威读取成功后才算确认；读取不可用不能转换为零条待处理消息。

写入回执和 POST 操作不进入隔离读取协议。回执处理可能执行写入核对，因此不能仅凭请求为 GET 就移入只读子进程。原有授权、幂等、执行准入和维护约束继续由各自原路径执行。

## 监督器生命周期

`node/supervisor.mjs` 以操作系统报告的子进程 `exit` 确认这一代 Core 已结束，只记录一次退出，并使用原重启退避策略。`close` 仅释放该代的流和日志引用：存活的后代可能在父进程退出后继续持有继承的 stdout/stderr。迟到的 `close`、spawn/error 回调或健康探测结果，必须核对实际 `ChildProcess` 身份，不能覆盖新一代状态。

此修复不会自动杀死仍存活但健康检查失败的 Core。经授权停止时，确认父进程退出即取消兜底终止计时器；不能为了关闭日志管道而杀死仍存活的后代。滚动日志写入器可跨代共享。停止时尝试排空该代 stdio 并刷新日志，合计最多等待 250 毫秒；超时后返回，不销毁继承管道。超过该期限的日志尾部不保证在调用方退出前刷完。

## 维护入口

- `src/console-workbench/read-protocol.ts`、`read-worker.ts`、`read-process.ts`：白名单、子进程执行和限制值。
- `src/db/client.ts`：只读数据库模式；`isolated-routes.ts`、`router.ts`、`feed.ts`：版本门禁、请求取消和共享刷新。
- `test/console-v5/console-read-process.test.ts`、`console-read-worker.test.ts`、`isolated-read-routing.test.ts`：超时、排队、只读和路由回归。
- `node/test/supervisor-exit-lifecycle.test.mjs`：真实继承管道、迟到关闭与探测、启动失败和有限尾日志刷新。使用仓库固定 Node 工具链，与原监督、维护和升级测试一起运行。

隔离限制了慢读取的影响范围，不等于已经证明历史节点冻结由哪条查询或 I/O 引起。诊断只记录固定路由、阶段、读取进程 PID、耗时和结果码，不记录查询内容或秘密。
