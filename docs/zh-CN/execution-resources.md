# 文件变更与并发

[English](../execution-resources.md) · 简体中文 · [首页](../../README.zh-CN.md)

QuayMesh 记录每项操作涉及的范围，让彼此独立的工作能够并行进行。

## 文件与项目范围

结构化文件操作申请它实际修改的文件。修改不同文件的操作可以独立执行，目录写入范围包含该目录中的文件。

普通终端命令使用项目范围。在 Git 项目中，默认范围是当前工作树；在包含多个项目的父目录中，默认范围覆盖该目录。

`working_directory` 决定命令的实际执行目录，`execution_scope` 声明用于调度的项目范围。进程能够访问哪些文件，由操作系统权限决定。

用户已授权读取的日志位于导出根目录之外时，可通过终端命令读取其本机绝对路径。需要交给结构化文件工具查看时，将所需文件复制到项目的诊断目录，并把执行范围设为该目标目录。

长时间运行的命令适合指定具体项目目录，让其他项目保持可用。

## 文件变化与快照

第一次修改前，QuayMesh 建立任务比较基准。结构化修改和文件传输提供目标路径，快照据此增量收集变化；普通命令会触发工作区变化收集。

Git 快照使用临时索引，保留用户已经暂存的修改。每个任务分别保存比较基准和文件摘要。

控制台展示已经保存的文件差异。恢复操作会检查修改归属和文件当前内容，再应用相应变化。

## 并行开发

需要独立代码副本的任务可以使用 Git 工作树：

```json
{
  "root_id": "worker/projects",
  "subdirectory": "my-app",
  "mode": "worktree",
  "base_ref": "main"
}
```

共享同一检出目录时，为操作选择不重叠的文件或项目范围。冲突结果会返回占用编号及资源范围。代理占用同时返回 `agent_id` 和已关联的任务，即使命令操作编号为空，也能查询或中断对应代理。占用持续到代理的实际执行结束。

## 命令配置

管理员可以在 `tools.commandProfiles` 中定义可重复使用的命令，包含可执行文件、参数、读取路径、写入路径和共享资源。

`${workspace}` 表示工作区目录，`${output}` 表示本次操作的输出目录。

这类配置适合固定构建、指标采集和读写位置明确的项目命令。

## 服务变更

安装和配置切换会检查已接收的操作，再替换相关组件。维护期间仍可以查询已有输出。

各节点报告实际运行版本和已应用配置，服务命令见[安装指南](INSTALL.md)。
