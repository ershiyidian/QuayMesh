# 生命周期可靠性

## 卡片与 Console 状态模型

会话卡片、全局 Console、项目 Console 和会话任务摘要分别保留三个事实：已保存的请求结果、观察到的后台执行和数据来源连接。连接失败不能改写已保存结果；已保存结果也不能遮蔽尚未核对的后台操作。

| 持久化请求 / 当前证据 | 主状态 | 独立信息 |
| --- | --- | --- |
| 已关闭，结果 completed | 已完成 | 后台执行或待核对回执继续显示 |
| 已关闭，结果 failed | 未完成 | 原始结果保持固定 |
| 已关闭，结果 cancelled | 已停止 | 剩余后台证据单独显示 |
| 已关闭，结果 handed_off | 已交接 | 已确认的后台执行可以继续 |
| 已关闭，没有确认结果 | 已结束 / 已归档，交付未确认 | 不能显示为已完成 |
| 开放，存在新鲜的活跃操作 | 执行中 | 最近输出距今多久、命令耗时 |
| 开放，存在新鲜的准备活动 | 准备执行 | 准备阶段与已经开始的命令区分 |
| 开放，没有后台操作 | 当前无后台执行 | 最近真实活动距今多久 |
| 开放，十分钟没有进展 | 长时间没有新的执行进展 | 不推断完成、失败或取消 |
| 开放，存在明确中断结果 | 执行已中断 | 近期无关活动不能擦除中断事实 |
| 执行证据缺失或过期 | 执行结果待核对 | 原有耗时停止增长 |
| 最终确认意图已落盘，证据采集未结束 | 交付确认中 | 最终确认成功前请求保持开放 |
| 最终确认失败 | 交付确认失败 | 保留错误；不能虚构任务终态结果 |

`task-view.ts` 提供共同的交付与执行规则。卡片和 Console 对已关闭请求优先展示交付结果，再展示后台和验收信息。执行筛选与中断操作继续依据真实执行状态。

项目归属决定哪些会话出现在项目中；这些会话中的每个任务，与全局任务列表使用同一份完整任务聚合，包括任务的其他工作区和节点。第二工作区有命令结果未知时，从第一工作区查看仍须显示。

某节点离线不能遮蔽另一节点仍然新鲜的执行观察。连接异常提示与仍可确认的操作分别显示。

卡片一旦接收任务身份，后续快照就不能移除或替换它。延迟快照不能让已关闭请求重新开放，包括结果仍然未知的归档请求。较新的命令回执和文件证据仍可补充到该请求。

业务版本与实时观察独立推进。同一个业务版本也可以更新连接和执行观察，无须重建未变化的文件或命令列表。延迟的业务快照不能覆盖更新的观察。轮询时间不属于执行进展。

## 计时与无活动提示规则

1. 任务耗时是从任务创建到有证据端点的墙钟跨度，不代表模型思考时间、CPU 时间或累计活跃执行时间。
2. 已确认的交付结束时间永久冻结任务耗时。归档请求没有已确认端点时显示未知耗时，不补造完成时间。
3. 开放请求只有在观察到真实执行、准备、停止过程或待完成的最终确认时才推进任务时钟。没有后台执行时，冻结在最近一次真实活动。
4. 命令只有在该命令具有新鲜活跃观察时才继续计时。终态命令使用记录的结束时间。证据过期或缺失时冻结最近确认的耗时；没有有效测量值时显示未知。
5. 执行观察在三十秒后过期。心跳或卡片轮询成功不能延长最近业务活动时间。
6. 无活动判断取最近真实工具、执行、输出或操作事件；没有此类事件时回退到任务创建时间。十分钟无进展会显示提示，即使任务从未开始命令。已确认仍在运行的命令即使没有输出，也继续显示运行。
7. 最近有活动或后台执行已确认时，每五秒读取一次，折叠卡片也一样。安静的开放任务展开时十秒、折叠时十五秒读取。已关闭但有待核对回执的请求每三十秒继续核对；已结束且无未决证据时停止轮询。

最近活动距今多久与冻结的耗时分别显示。读取失败显示自动重连提示，不覆盖已保存主结果。窄屏保留完整状态说明和所有详情标签名称。

## 历史卡片协议兼容

当前资源为 `ui://quaymesh/task-card/v7.html`。历史对话会永久保留资源地址，因此实际发布过的 v1、v3、v4、v5、v6 地址继续注册。

资源地址与渲染器协议能力分别处理。历史地址提供当前渲染器时，该渲染器的每次 `qm_session` 请求都声明 `task-card-v7`。历史地址仍用于卡片诊断，但不能强迫当前 JavaScript 请求裁剪后的旧载荷。

| 读取器实际能力 | 快照 / 实时回执 |
| --- | --- |
| v7 | 完整快照、执行观察、轻量连接与执行实时状态、结构化最终确认状态 |
| v6 | 保留执行观察与来源任务身份；移除仅 v7 认识的 live/finalization 字段 |
| v1、v3、v4、v5 或未声明 | 历史严格快照结构；移除后续新增的 observation/live/finalization 字段 |

持久化快照保留完整数据。兼容转换发生在响应边界，旧缓存读取器可继续使用，当前读取器所需的证据也不会丢失。当前展示端容忍未知的新增字段，同时继续拒绝损坏的已知字段。

## 宿主事件与归因边界

QuayMesh 能观察自己的工具调用、进程、持久记录和 App 桥接。它没有一种普遍可靠的事件，可以证明宿主已经结束思考、渲染最终回答，或把该回答交给用户。

因此，宿主回答后没有调用 `finish_task` 时，卡片展示可观察的事实：当前无后台执行、耗时暂停、最近真实活动距今多久。不能根据时间流逝或 App 连接正常推断成功。

`finish_task` 在有界等待后可以返回 `state=finalizing`、`accepted=true` 和重试/查询动作，但前提是匹配的最终确认意图已经持久化。请求的结果状态此时还不是已确认的任务结果。服务继续持有工作占用并进行真实证据采集，最终确认成功后才写入 `closed` 和最终结果。重复相同意图复用该工作，冲突意图被拒绝。

通常观察预算为两秒；数据库锁阻塞时必须先等意图落盘，不能为满足时限伪造受理。归档恢复调度跨轮最多保留四个入口/执行节点归档工作，每轮最多观察两秒；挂起的归档继续持有维护占用，其他空闲槽位可以完成后续任务，同一任务不重复发起归档。

事故归因必须保留下列边界：

- **C09：** 卡片实时观察和持久受理/查询契约能提供 QuayMesh 进展，但不能证明某个宿主支持进度通知或已经消费了通知。
- **D09：** HTTP 响应结束、RPC 成功、工具结果、操作影响和宿主接收确认是不同事实。本地 `200` 或已保存工具响应不能证明宿主接收；缺失的接收确认继续记为未知。
- **D10：** 宿主显示 `message timeout` 或 `thinking failed` 时，必须有时间戳和匹配的 request/operation 跟踪才能归因。缺少宿主/提供商证据，不能宣称 GPT 故障，也不能计算 QuayMesh 导致失败的精确占比。

浏览器验收覆盖真实本地 MCP 会话、SQLite 最终确认意图、待确认到已关闭的证据采集、过期/丢失回执、历史资源地址，以及全局/项目/会话的一致性。浏览器测试能验证渲染和协议行为，不能代替宿主的交付接收确认。

## 激活与验收

使用 Node 24.21.0、冻结的依赖锁和干净 Git 提交构建平台发行包。`release.json` 标识实际打包的 Node 与原生依赖字节；`verify-installed.mjs` 在改变服务前运行真实 SQLite/GC 和 schema 检查。

发行准备与运行安装分开。激活前重新检查准入、排队工作、claim、代理、命令进程和出口流。安装器制作在线 SQLite 备份，保存切换状态，更换服务并等待稳定实例。验证后的激活提交完成，才恢复准入。提交后恢复准入失败时保留新服务，继续核查。

安装切换标记同时约束 manager 和 Core。新 Core 在建立对外执行通道前读取标记，验证期间拒绝新修改和出口流；只读诊断仍可用。标记存在时直接调用 Core 的恢复准入接口也会被拒绝，删除标记后仍须安装器明确恢复。

Windows 从预期服务用户的已授权会话运行 `node/windows-activate.ps1 -PreparedManifest <prepared.json>`。一次性计划任务独立于旧 Host Job，保存自己的结果和日志，不停止独立 EasyTier 或用户进程。该次激活结束后删除其 Task Scheduler 登记。

旧部署可能保留没有存活 owner 的历史未知回执。不能为了通过空闲检查删除回执或解除 claim。旧版引导升级需要独立证据：准入已暂停，多次检查均无活动/排队工作，进程身份与进程组已确认，没有活动代理流。死 claim 的后代尚未核实退出时阻止自动激活；历史不确定性继续保留在新数据库。

当前实现不承诺 Core 持有的命令管道/PTY 透明跨重启存活。必须跨 Core 服务替换继续运行的工作，应使用独立服务或持久作业调度器。忙碌或断连节点保留当前安装，待能核查并排空后再升级。
