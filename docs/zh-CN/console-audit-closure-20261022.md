## 原 85 项逐项处理

“保留的边界”包含数据本身无法证明的事实和尚未实施的大型设计扩展。已修复已确认的错误路径，不把完整等待编排、持久增量索引或跨根原子回滚写成已经交付。

### 状态与生命周期

| 编号与原问题 | 本次实际变化 | 验证入口 | 保留的边界或结果解释 |
| --- | --- | --- | --- |
| **S01** 全局收尾尚未完成，控制台已经显示完成 | 交付确认记录进入 SQL、Task 摘要和卡片；pending/error 保留到 owner 最终确认。收尾完成与关闭 Task 在同一事务提交，失败可恢复。 | L | 不把执行端先结束等同于整个请求交付完成。 |
| **S02** 待核对的 Run 可以被 finish_task completed 越过 | 结束请求前检查 Run、命令和代理的活跃及未决事实；unknown/reconciliation_required 不可被 completed 越过。 | L | 交接可保留后台事实；不伪造历史副作用已经消失。 |
| **S03** 最后代理已失败或被中断，任务却变成等待下一步 | 选择最后有意义的子执行结果，失败/停止不会被 read/search 擦掉；成功接续可替代旧失败。Console 与卡片共用结果选择。 | L,Q | 同毫秒按真实插入顺序；不同成员和新 Task 不继承旧失败。 |
| **S04** 等待下一步没有真实的等待对象、责任人或退出条件 | 去掉没有证据的“等待下一步”，统一为“当前无后台执行，请求仍然开放”；静默提示只描述进展时间。 | L,U,B | 尚未引入等待对象、负责人、外部依赖、解除条件的完整业务模型。 |
| **S05** 新阶段会遮住旧阶段尚未解决的未知或中断 | current phase 与仍相关执行分别选择；旧 unknown、未解决中断参与索引、详情、注意事项和控制目标。 | L,F | 没有因新阶段创建而自动清除旧未知。 |
| **S06** 旧请求关闭会把未知后台状态盖成已结束 | 请求关闭、交付结果与后台事实独立保留；fresh active/unresolved 优先呈现真实执行情况。 | L,F | 已有 completed 结果不会把后台 unknown 改成成功。 |
| **S07** 明确的 handed_off 交接语义在控制台丢失 | 保留 handed_off/resultStatus；有后台时同时呈现交接与执行事实，无后台时仍显示已交接。 | L,U | 没有不存在的接管者信息；结构化接管人模型尚未新增。 |
| **S08** 已经创建、尚无 Run 的 Task 在全局总览和任务列表消失 | 生命周期索引补入无 Run 的 Task，带真实 Task revision、owner、成员和工作区；列表、详情及结束请求均可使用。 | L,F | 没有为展示制造虚假物理 Run。 |
| **S09** 任务已显示完成，结束时间却可能为空，列表与详情口径不同 | 相关阶段集合与结束时间口径统一；修复有意 null 被旧 Run.finished_at 覆盖；请求交付结束保留独立时间。 | L,Q | 历史未知时长继续未知，不用当前时间冒充结束。 |
| **S10** 等待接续和结束待确认既不进入待处理，还可能被时间筛选隐藏 | 共享 needsAttention 包含 stalled、finalizing、unknown、失败及未解决中断；旧创建时间不再隐藏待处理项。 | L,F | 静默时间不会单独推断业务失败。 |
| **S11** 结束并验收只结束 work run，真正的业务 Task 仍可能开放 | 阶段验收与结束请求分离；请求开放且阶段 completed 时保留阶段结果、待验收能力和请求开放事实。结束请求经 owner+Task CAS。 | L,C,B | 人工接受结果不再偷偷等同于业务请求已结束。 |
| **S12** 状态枚举更新了，实际状态徽章没有同步 | 状态 key、标签、stopping/handed_off、分组和卡片使用共享映射；界面保留明确请求/阶段维度。 | L,U | 历史未识别字段仍提供可诊断错误。 |

## 仍保留的设计边界

1. **没有证据的副作用仍需核对。** 不能把未知批量标完成；归档/控制的查询不重放未知动作。
2. **等待及交接尚无完整业务编排。** 不再用不实等待文案；责任人、外部依赖、解除条件、接管者需要真实业务数据。
3. **全局增量索引未重建。** 已删除可证明重复的查询路径和不必要分类；完整历史 Task 聚合仍有必要的历史成本，没有线上性能倍数承诺。
4. **跨节点读取不是原子快照。** 显式刷新和同批阶段头部解决缓存混合；读后发生新事件仍可合法触发 CAS。被拒绝且 effect=none 的意图允许刷新后用新 key 提交。
5. **跨工作区还原仍按阶段。** 已有可达入口、来源和版本保护；没有声称多个根目录的原子回滚。
6. **观测与通知能力有真实边界。** 缺首响应的历史不伪造；未测速度不显示；用量按执行轮次完成日确认；通知依赖浏览器前台读取。
7. **界面模块并非全部重写。** 状态/时间/回执/通知/配置合并已共享或拆出，主界面文件仍较大；技术对象导航仍存在。
8. **本轮观察到连接作用域切换，但未归因为本地代码缺陷。** 原会话出现 scope mismatch 后按当前授权会话重新附加；没有越过作用域限制，也不把它计作已经修复的产品 bug。
