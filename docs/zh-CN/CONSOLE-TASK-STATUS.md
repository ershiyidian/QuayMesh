# 控制台中的任务状态

[English](../CONSOLE-TASK-STATUS.md) · [简体中文](CONSOLE-TASK-STATUS.md)

任务主徽章描述已保存的工作目标。任务仍然开放时，即使没有命令运行、某次试验命令失败，或者正在等待下一步决策，也保持**任务进行中**。这个徽章不表示模型或进程此刻一定正在执行。

后台执行、结果验收和来源数据的新鲜度分别显示：

| 证据 | 显示 |
| --- | --- |
| 任务开放，没有后台命令运行 | 任务进行中，副徽章显示当前无后台执行 |
| 任务开放，命令失败 | 任务进行中，副徽章显示最近执行失败 |
| 交付确认进行中或失败 | 显示已保存的确认状态，后台执行情况另列 |
| 任务已结束且结果已保存 | 显示已保存结果；迟到的运行回执或未知执行结果仍作为副徽章保留 |
| 来源观测过期或暂时不可用 | 独立显示上次确认，不据此改写已保存的任务生命周期 |

**进行中**和**已结束**范围分别筛选已保存的 `active` 和 `closed` 状态。**后台执行**筛选执行中、正在停止或排队的工作。这些范围表达不同事实：已结束的任务仍可能存在需要核对的后台执行回执。

打开任务详情后，列表旁仍可使用任务生命周期选择器。切换列表范围不会改变已经打开的详情或待确认操作的目标。切换生命周期范围会返回列表第一页。开放和结束范围的数量依据同一组机器、项目、搜索和时间条件统计，选择其中一项不会让另一项数量变成零。

近期时间范围会保留开始时间更早的开放任务。明确选择的日历日期仍会限制结果。缺少可靠 Task 生命周期的历史记录保留在**全部**及其已知执行状态筛选中；控制台不会替它们推断开放或结束。

总览中的后台执行数量继续依据实际执行观测统计。因此，最近执行结果区可以包含执行阶段已经完成或失败、工作目标仍然开放的任务；其主徽章继续显示 Task 生命周期。

现有任务读取接口接受 `requestState=active` 或 `requestState=closed`，例如：

```text
/console/api/v4/runs?requestState=active&days=7&limit=25
```

`running` 等执行状态不能用作 `requestState`。分页游标属于原来的筛选条件；不要将进行中范围的游标用于已结束范围。
